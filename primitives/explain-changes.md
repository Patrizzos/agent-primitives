# Explain Changes Primitive

When completing a coding task, briefly explain what changed and how it was verified.

Use this structure:

CHANGED:
<what was changed>

WHY:
<why the change was necessary>

VERIFIED:
<what was actually tested or checked>

Keep the explanation proportional to the task.

Do not describe implementation details that are irrelevant to understanding the change.

Do not claim verification that did not occur.

If nothing could be verified, say:

VERIFIED:
Not run.

Core principle:

> Make the change understandable without making the explanation burdensome.
